Embeddings, Similarity, and Vector Storage

Module 8, Lecture 8.2 | Retrieval-Augmented Generation (RAG)

Vector search is the most common way to implement RAG, and this lecture places each of its pieces in the pipeline from Lecture 8.1, using a customer support knowledge base as the running example. An embedding model is a separate, smaller model from the LLM: it turns a passage into one vector, trained with contrastive objectives so that similar meanings produce nearby vectors. Retrieval embeds the user's question and finds the closest stored vectors by cosine similarity, a normalized dot product, which is why "I'm locked out of my account" can find an article on password resets that keyword search would miss. Embedding APIs from Voyage AI, OpenAI, and Cohere are cheap, but the choice is sticky: vectors from different models cannot be compared, so switching means re-embedding the corpus. A Python dictionary with a linear scan is enough for a small corpus; vector databases add approximate nearest neighbor indexing such as HNSW, persistence, and metadata filtering, and know nothing about LLMs. Chunking splits documents for granularity and window fit, and library defaults are a sound start. The lecture closes by wiring vector search as a tool in the agent loop, where the model sends a query string and gets back text without ever seeing a vector, and by naming where vector RAG fits and where the retrieval methods of Lecture 8.3 do better.

Additional Resources

  • Lecture slides
  • Embeddings — Anthropic docs. Anthropic does not offer its own embedding model; this guide covers Voyage AI's models, their dimensions, and shortening vectors to save storage.
  • Vector embeddings — OpenAI docs. Default dimensions for text-embedding-3-small and text-embedding-3-large, shortening vectors with the dimensions parameter, and a worked cosine-similarity search.
  • Dense Passage Retrieval for Open-Domain Question Answering — Karpukhin et al., EMNLP 2020. A dense retriever trained on question-passage pairs beats BM25 keyword search by 9–19 points in top-20 accuracy; the evidence behind embedding search over keyword search.
  • MTEB: Massive Text Embedding Benchmark — Muennighoff et al., 2022. Finds that no single embedding model wins on every task, and is the basis of the public leaderboard used to compare models.
  • Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs — Malkov and Yashunin. The HNSW paper: the layered-graph index behind approximate nearest neighbor search in most vector databases.
  • Introducing Contextual Retrieval — Anthropic, 2024. Shows how chunks lose context once split from their documents, and how adding that context back before embedding cuts retrieval failures by 35–67%.
  • Chunking Strategies for LLM Applications — Pinecone, 2025. Fixed-size, sentence and paragraph, and semantic chunking, with guidance on choosing and evaluating chunk sizes.
  • Chroma documentation — An open-source vector database that runs locally, stores documents with metadata, and supports metadata filtering.
